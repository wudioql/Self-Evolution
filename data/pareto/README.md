## 两个口径：记录 vs 事件

同一次报警常跨两个班次甚至几天，交接表会留下多条记录。直接按记录数统计会重复计数，所以报告同时给两套数字：

| 口径 | 含义 | 用途 |
|---|---|---|
| **记录级** | 交接表里的每一行算一次（125 条 / 报警类 112 条） | 还原交接工作量与原表原貌 |
| **事件级** | 按 `eventGroups` 把同一事件的跨班记录合并（103 起 / 报警类 91 起） | 比较各类别真实发生频次、排帕累托 |

页面顶部有「事件级 / 记录级」切换按钮，明细表同时列出两列。

### 配置字段

- `eventGroups`：`[{rows: [行号...], note: "归并依据"}]`。组内行号必须存在、同类别、不与其他组重叠；合并后日期取最早一条，`DOWN` / `MON PA` 取组内任一。**只登记人工确认过的事件**，不靠文本相似度自动归并（实测会误并/漏并）。确属同一事件但主诉类别不同时（如颗粒 NG 由密封圈泄漏引发），用可选的 `cat` 字段指定归入哪一类，否则校验会拒绝。
- `pendingGroups`：格式相同，但**不参与合并**，只用于说明「待确认的候选组」并在报告里给出最多可再减多少起。确认是同一事件后移入 `eventGroups`，确认不是就删掉。

## 原始表格式

- Markdown 表格；表头必须含 `日期`，列数等于配置里的 `columns`；
- 首列 `#` 为记录序号（1 起，连续），分类配置用它定位记录；
- `MON PA` 列用 `✔` 标记；`EQP Status` 列用 `DOWN` 等原值；
- 表头之前的内容（来源说明、统计摘要）会被自动跳过。

## 做下一份（同机台延长时间，或另一台机台）

1. **复制配置**，改 `title` / `period` / `input` / `output` / `generatedOn`。
2. **重新归类**：把每条记录的行号写进对应 `categories[].rows`。保持三条硬规则：
   - 一条记录只进一个类别；
   - 按「情况描述」的**主诉现象**归类，不按处理动作、不按 EQP Status；
   - 计划保养 / 复机单独设 `excluded: true` 类别，从报警口径剔除。
3. **跑 `--check`**：行号必须全覆盖、无重复、无越界，否则不生成。
4. **登记事件归并**：逐条看跨班 / 跨天的相邻记录，人工确认后写进 `eventGroups`；拿不准的放 `pendingGroups`，不要靠相似度脚本猜。
5. **重写 `top3` 与 `caveats`**：只写数据能支撑的判断；证据不足写「待验证」，不猜。
6. **生成并核对**：数字与原表统计摘要交叉核对（如按年份、按措施分类），再用浏览器打开确认渲染。

## 隐私边界

- 原始表必须用 `*.local.*` 后缀，绝不入库；
- 配置里只放**行号**与**通用类别名**，不写机台编号、报警代码、人员姓名；`eventGroups` 的 `note` 也只写通用描述，不写具体测量值或腔体 / 片位标识；
- 带真值才看得懂的备注写进同名 `*.local.json`（如 `报警帕累托-…-2025-08_2026-10.local.json`），`*.local.*` 已被 `.gitignore` 覆盖；公开版继续作为生成器输入，两份并存、输出不变；
- 产出页面只含类别、次数、月份等聚合信息；生成器不会把 `desc` / `action` 原文写进页面；
- 公开前跑 `python scripts/check-docs.py`（含真值泄露扫描）。

## 形式定制

- 配色、字号、布局改 `report-template.html` 的 CSS；图表仍是内联 SVG，无外部依赖。
- 要加维度（如停机时长、班别）时：先确认原始表有该列，再加进 `columns` 与模板，不在页面里手填数据。
