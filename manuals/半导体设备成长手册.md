## 2. 核心方法

### 2.1 为什么必须是"问题驱动"

| | 系统读书 | 问题驱动 |
|---|---|---|
| retention | 低（没有应用场景，两周就忘） | **高（知识直接挂在一个你亲手处理过的问题上）** |
| 动力 | 靠意志力 → 会在第 4 周死 | 靠"这个问题明天还在" → 天然持续 |
| 时间 | 需要整块时间 | 可以碎片化 |

**而且**：你的设备知识**在工作中学得最快**（天天摸机台）。
业余时间的价值不在于"多学一点设备"，而在于**补上工作中学不到的那部分**：
① 原理层（为什么这么设计）② 系统化沉淀（故障库）③ 数据（用数据说话）④ 英语。

**操作步骤**：
```
① 上班遇到一个问题（如 matcher 又跳了）
② 用 20 分钟查这一个知识点（阻抗匹配与反射功率）
③ 处理完 → 记进故障模式库（含排查路径和走错的路）
④ 周末有空时，把这个知识点往上下游各延伸一层
```

### 2.2 七大知识块（按你的机台排优先级）

#### ★★★ 真空技术（你所有机台的共同底座）

| 要懂 | 内容 |
|---|---|
| 真空获得 | 旋片泵 / 罗茨泵 / 分子泵 / 低温泵的原理与适用量程 |
| 真空测量 | 皮拉尼规 / 电容薄膜规 / 电离规的**量程与适用段**（用错规是常见误判来源） |
| 流态 | 粘滞流 / 分子流的判据（克努森数），影响抽速与管路设计 |
| 放气 | 材料放气率、水汽吸附、烘烤的作用 |
| ⭐ **氦质谱检漏** | **设备工程师最实用的一项硬技能，优先掌握** |

#### ★★★ 气体与化学输送（扩散 / 退火 / CVD 的核心）

| 要懂 | 内容 |
|---|---|
| MFC | 热式 / 压差式的原理、标定方法、温漂与零点漂移 |
| 阀件 | 隔膜阀 / 波纹管阀 / 气动阀的失效模式 |
| ⭐ 特气安全 | SiH₄（自燃）、NH₃（毒性与腐蚀）、N₂O（助燃）、TEOS / O₃、掺杂气体的特性与应急处理 |
| 尾气 | scrubber / burn box / cold trap 的原理与维护要点 |
| 纯度与颗粒 | 气体纯度等级、过滤器选型、颗粒来源 |

#### ★★★ 热工与温控（炉管 / 退火 / RTA 的核心）

| 要懂 | 内容 |
|---|---|
| 加热元件 | 电阻丝 / 卤素灯 / 红外的特性与失效模式 |
| ⭐ **PID 整定** | P / I / D 各自的**物理意义**与调参手感（超调、震荡、稳态误差分别调哪个） |
| ⭐ 热电偶选型 | K / E / J / S / R / B 型的量程与适用 —— **SiC 高温退火要用 S / R / B 型，记住为什么**；冷端补偿；补偿导线 |
| 热场与均匀性 | ramp / soak / profile、温度均匀性测试（TUS / profile TC） |
| Thermal budget | 时间与温度对工艺结果的等效性 |

#### ★★☆ RF 与等离子体（PECVD 的核心，也是最难的一块）

| 要懂 | 内容 |
|---|---|
| RF 系统 | 13.56 MHz 电源、传输线、功率计 |
| ⭐ **匹配网络（matcher）** | **你调 PECVD 天天在跟它打交道**：阻抗匹配原理、C1/C2 调谐、反射功率的意义 |
| 等离子体基础 | 辉光放电、帕邢定律、E / H 模式转换、自偏压 |
| 诊断 | OES（发射光谱）能告诉你什么 |
| 常见故障 | 起辉失败、反射功率高、等离子体不稳定、电弧（arcing） |

#### ★★☆ 控制与自动化

| 要懂 | 内容 |
|---|---|
| PLC | **能看懂梯形图就行，不用会写** |
| 传感器 | 光电 / 接近 / 压力 / 编码器，各自的失效模式 |
| 气动 | 气缸 / 电磁阀 / 真空发生器 |
| ⭐ 安全回路 | interlock、E-stop、安全继电器的逻辑（**这是设备工程师的底线责任**） |
| 通信 | SECS/GEM 基础 —— 知道**数据从哪来**，为后面取数做准备 |

#### ★☆☆ 激光系统（**当前厂区特有，差异化优势**）

| 要懂 | 内容 |
|---|---|
| 安全 | 激光等级、防护、互锁（优先级最高） |
| 光路 | 镜片、光路准直、污染与损伤 |
| 光束 | 整形 / 匀化 / 扫描系统 |
| 工艺 | 脉冲与热积累、能量监测与衰减趋势 |

#### ★☆☆ 量测与检测

| 要懂 | 内容 |
|---|---|
| 膜厚 | 椭偏仪 / 反射光谱的原理与适用边界 |
| 电性 | 四探针方块电阻 |
| 其他 | 应力、表面粗糙度、颗粒检测 |

### 2.3 ⭐ 故障模式库（设备纵深路线的核心资产）

**为什么是它**（四条理由）：
1. 逼你把经验系统化 —— 从"我会修"到"**我讲得清为什么**"
2. 它是**带人的教材**，而带人是走向主管的门票
3. 它是晋升答辩时**唯一能拿出来说的东西**
4. 它符合你"知识整理"的天性，且可以用 vibe coding 做成可检索网页

**存放方式**：真实记录统一放 `data/faults.local.json`；agent 自动生成本地 Markdown / HTML 供查看。
示例不计真实条数，未知根因 / 是否复发 / 是否解决 / 时长留空待确认；不要为了凑数编造。
操作与保密边界 → [`AI与工具手册.md`](AI与工具手册.md) §4.6。

**每条记录的标准格式**：
```
【机台类型】【机台型号】【机台编号】【报警代码】  ← 敏感字段
【现象描述】【发生条件】（recipe / 步骤 / 频率 / PM 后多久）
【排查路径】1 → 2 → 3，我实际怎么查的
             ⭐ 把走错的路也记下来 —— 排除法本身就是知识
【根因】      ⭐ 物理/机理层面的原因。不是"零件坏了"，而是"为什么它会坏"
【处理措施】
【预防 / 改善建议】⭐ 这一栏是改善提案的直接来源
【停机时长】【是否复发】【是否彻底解决】
```

**执行建议**：**先录 30 条你亲身处理过的，再追求体系完整。**
不要一上来就想做一本完美的手册 —— 那会变成你的第 6 个 80% 工程。

### 2.4 改善项目方法论（W6–W8 要用）

| 方法 | 什么时候用 | 要点 |
|---|---|---|
| **5-Why** | 单独一个故障的根因 | 连问 5 次"为什么"，直到问到**物理/机理层** |
| **鱼骨图（石川图）** |  brainstorm 可能原因 | 人 / 机 / 料 / 法 / 环 / 测 六个维度 |
| **FTA（故障树）** | 复杂系统、多因耦合 | 自上而下，用与/或门展开 |
| **FMEA** | 预防性、在设计/导入阶段 | 严重度 × 发生度 × 检出度 = RPN，优先降高 RPN |
| **8D** | 对外的正式报告 | D1 建组 → D2 描述问题 → D3 临时措施 → D4 根因 → D5 永久措施 → D6 实施 → D7 预防再发 → D8 表彰 |

**改善提案的写法（一页就够）**：
```
① 现状与问题（附数据：近 N 个月报警 X 次，停机 Y 小时，损失 Z）
② 根因分析（附帕累托图，指出 Top 1）
③ 建议措施（具体、可执行、有责任人）
④ 预期效果（可量化：预计报警降低 __%）
⑤ 所需资源（备件 / 工时 / 费用）
```

> **资深工程师和主管的区别，往往就是：**
> 一个人说"这台机最近总报警"；
> 另一个人拿出一张图说"这台机近 3 个月 A 类报警 47 次，其中 31 次集中在 PM 后 48 小时内，Top1 根因是 X，建议改 PM 项 Y，**预计可降 60%**"。

### 2.5 数据能力路线

**目标不是"学会 Python"，是"能用数据说话"。**

| 阶段 | 内容 | 产出 |
|---|---|---|
| 1 | 已有表格工具，或获准的本机 agent 代写 / 运行脚本；本人选问题、核对结果 | 能解释 log 与图，不要求本人学习 Python |
| 2 | **SPC**：控制图、Cpk / Ppk、八大判异准则 | 能判断机台是否"在控制内" |
| 3 | **帕累托分析**（W6–W8 用这个） | 报警 Top N 根因 |
| 4 | 可靠性：MTBF / MTTR、Weibull | 备件策略 |
| 5 | DOE / 相关性分析 | 找参数与结果的关系 |
| 6 | FDC（故障检测与分类） | 提前预警而不是等报警 |

> ⛔ **工艺侧的 DOE 不在你的 90 天范围内**（那是工艺路线的工具）。
> 90 天只按 JSON 完成一张帕累托图和提案；阶段表不是必须从 1 通读到 6 的课程。

**关键原则**：**用你自己的产线数据练（脱敏后），不要拿玩具数据集。**
你懂机台，你知道哪些数据有物理意义 —— **这是纯 CS 出身的人做不到的，是你的护城河。**

### 2.6 英语：术语表法

**你的六级水平已经够了，缺的是"用"。**

**做法**：
1. 打开你负责机台的英文 **Service Manual**，从 Chapter 1（安全 / 规格）开始
2. 边读边把术语记进一个表（可以放进墨墨，你已经有 SRS 习惯）
3. 90 天目标：80 个词

**预期用途**：更准确地查阅手册、参与原厂培训与新机台导入沟通；不保证相对同事的排名，也不把已放弃的原厂 FAE 路线重新设为目标。

## 4. 进阶路径（1–8 年）

| 阶段 | 目标 | 关键动作 |
|---|---|---|
| **现在**（3 年经验） | 从"能修" → **"能讲清为什么 + 能预防"** | 故障模式库 + 帕累托图 + 改善提案 |
| **3–5 年** | 主导一个机型的改善项目 / 国产设备导入 / 开始带 2–3 人 | 主动争取项目主导权；把故障库变成培训教材 |
| **5–8 年** | 设备主管 / 设备技术专家 | 从"管机台"到"管人 + 管体系 + 管成本" |

**每个阶段的跃迁判据**：

| 跃迁 | 判据 |
|---|---|
| 资深工程师 → **专家** | 别人解决不了的问题你能解决，且**能讲清楚为什么** |
| 专家 → **主管** | 你不只自己能解决，还能**让 3 个人都能解决** |
| 主管 → **经理** | 你不只解决问题，还能**决定解决哪个问题**（成本视角） |

> **职业岔路已确认，不再安排“设备还是工艺”的试探任务。**
> W9 的提案反馈 / 小验证依任务 `9-2` 执行；任何现场验证先走批准流程，不自行改机台参数。
