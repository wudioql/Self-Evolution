## 4. 各模块用法

### 4.1 ComfyUI → 歌的封面（W12）

**流程**：
1. 先用你已有的工作流跑几张
2. 挑一张 → 需要改的地方用局部重绘（inpainting）
3. 加文字（歌名 / 你的名字）→ 这一步用 kdenlive 或任意图像工具做更省事

**建议**：**先把工作流固定下来并保存为模板**，W12 时直接调，不要现场搭。
现场搭工作流 = 必然超时 + 必然触发"工具折腾"。

### 4.2 视频（W12，kdenlive，你已 star）

**最低可行方案**（30–60 秒）：
```
静止封面 + 音频频谱条 + 歌词字幕
```
这就够了。**不要试图做 MV。**

**流程**：
1. ComfyUI 出封面 → 导入 kdenlive
2. 铺上音频轨
3. 加一个频谱可视化（kdenlive 有内置效果，或用插件）
4. 用你自己的 `Qwen3-Subtitle-Studio` 生成歌词字幕 → 导入
5. 导出 1080p

> ⭐ **第 4 步是这 90 天里情绪回报最高的一个动作**：
> 你写的工具，终于被你自己用上了。

### 4.3 音乐 AI（ACE-Step 1.5）

**定位：草稿机，不是成品制造机。**

| 可以用它 | 不要用它 |
|---|---|
| 生成 30 秒的动机/氛围草稿 | 直接生成一首歌当成品发出去 |
| 探索你不熟悉风格的和声与配器 | 替代你的扒带训练 |
| 做一个"如果这样编会怎样"的快速验证 | 当成"我做音乐"的替代品 |

**理由**：你的目标是**练出自己的音乐能力**。
AI 生成得再好，也不会让你学会听和弦。**把它当灵感跳板，不当终点。**

- 应对：ComfyUI 开低显存模式 / 模型 offload；关注社区量化版
- ⛔ **做好"慢"的准备，但不要为此折腾超过 2 小时**（→ §2 三条纪律）

### 4.4 vibe coding（你已确认：不打算学编程）

**这是完全 OK 的。** 你的目标不是成为程序员。

**但你确实需要学一件事：怎么提需求。**

一个能被 AI 正确实现的需求，需要说清四件事：

| 要素 | 例子 |
|---|---|
| **输入** | "一个导出的 wav 文件 + 一个 txt 歌词文件" |
| **输出** | "一个 srt 字幕文件，字级时间轴" |
| **边界** | "只处理中文和日文；文件超过 10 分钟要能跑" |
| **失败案例** | "如果某一行识别不出时间，就跳过而不是崩溃" |

**三条实用建议**：
1. **让 AI 顺便写 README 和安装说明** —— 否则三个月后你自己都装不回去
2. **让 AI 解释它做了什么**（用你能懂的话），而不是让你读代码
3. ⛔ **不要试图读懂代码**。你已确认不学编程，那就别在这个环节卡住

### 4.6 文件记录与 agent 协作（默认用法）

**只保留一份正本，生成多个查看入口。**

| 内容 | 正本 | 自动生成视图 |
|---|---|---|
| 排期、任务状态、备注、证据、打卡 | `progress/plan90.json`（v2） | `progress/进度总览.md`、`tools/90天进度表.html`；`03` 逐周表 |
| 真实故障、排查、根因、预防、配置 | `data/faults.local.json`（v1） | `data/故障模式库.local.md`、`tools/故障模式库.local.html` |

#### 对话工作流

1. 用户问任务 → agent 运行只读 `today`，按日期、当前状态和夜班安排选一个优先动作。
2. 用户明确报告进展 → agent 找稳定 ID；一小步写 `note`，整项才 `done`。保存证据路径 / 链接和实际日期。
3. 用户要求打卡 → 单独记录；同一天不重复累计，不根据勾选数量推测学习时长。
4. 故障口述 → agent 按半导体手册 §2.3 整理；未知字段留空。真实记录不写进公开进度备注。
5. 每次写入 → Python 脚本先校验，用同目录临时文件 + 原子替换；保存旧内容到相邻 `.backups/`（每个数据文件最近 20 版），再生成所有视图。
6. 用户只在想看全貌时打开视图。查询没有副作用，也不是后台定时提醒。

运行需要 Python 3.11+ 标准库，无 Web 服务、数据库、项目 `.env` 或部署步骤。**这是 agent 的操作要求，不要求用户学习编程或每天敲命令**；Windows 可将 `python3` 换为已安装的 `python` / `py -3`。
Node 20 用于 HTML 语法和文件桥测试；真实浏览器冒烟另需 `python3 -m pip install playwright`、`python3 -m playwright install chromium`，Linux 缺浏览器系统库时由有权限的维护者安装依赖。它们不是查看 HTML 或日常记录的依赖。

#### 数据约定与恢复

- `meta.day0 / day1 / day90 / end` 是日期基准；`dailyPlan` 覆盖 Day 0–98。日号按上海时区的自然日计算，不按经过的 24 小时累加。
- `weeks[].tasks[]` 的 `id` 稳定；`scheduledDate / dueDate` 是排期；`done / completedOn / note / evidence` 是状态。移动任务不改 ID。
- `weeks[].note` 留周备注；`checkins` 日期去重；`dailyLogs` 记实际分钟与日志；`overrides` 记确认的夜班 / 低能范围。
- `history` 留变更；`_orphans` 留旧备份中找不到的 ID。**同步脚本不改正本，也不清空历史。**
- 故障 `items[]` 中 `isSample=true`（以及旧示例标记）不计成果；`isRecurring / isSolved / downtimeMin` 的 `null` 表示未知，不是“否 / 0”。
- 写入冲突会拒绝覆盖。先重读正本，对比 `.backups/` 与当前内容，再让 agent 合并；不要用旧页面强行覆盖新文件。
- Python 编辑有协作锁；浏览器采用串行写与写前对比。**这不是跨进程数据库事务**：不要让两个 agent / 浏览器同时编辑同一个 JSON。
- 若 JSON 已写入但视图生成失败，脚本会明确提示“JSON 已保存”；只需再同步，别重复新增记录。
- 20 版自动备份由 Python 写入路径提供；浏览器仅能写授权的 JSON，不能顺带生成旁边的备份目录。
- v1 回滚副本是迁移前历史，不可直接覆盖 v2 正本；旧格式用 `import-plan` 并入状态，保留原件。
- **异常导入整包停止（2026-09-06 本人确认）**：先校验所有传入状态；不合法日期 / 字段使整包失败，正本与备份原件不变，不静默跳过或猜日期。合法的同日记录仍去重；未知 ID / 周备注归 `_orphans`，不计作当前任务完成。
- 打卡 / 每日记录须在计划内且不晚于实际日期；任务完成日期可真实提前或延后，但不能在未来。缺失日期保持未知。查询未来排期不会改变这个校验基准。
- Python 与网页使用对应的同一套字段约束，并用同批输入交叉回归。生成标记缺失、重复或倒置直接报错，不自动补标记或假报同步成功。
- B1–B8 修复与验证记录见 [`../维护审计.md`](../维护审计.md)。真实浏览器维护检查运行 `python3 scripts/browser-smoke.py`，默认用隔离数据和四个固定日期；不读取用户完成状态来当测试样例。

#### 给 agent 的常用命令（在项目根目录执行）

```bash
# 查询：只读，不打卡、不勾选；不带日期时按运行当天的 Asia/Shanghai 计算
python3 scripts/progress.py today
python3 scripts/progress.py today --date 2026-09-07 --mode low

# 以下只是用法示例；没有本人确认，不能执行 done / checkin
python3 scripts/progress.py done 1-0 --on 2026-09-06 --note "本人确认已弹响"
python3 scripts/progress.py undo 1-0 --note "更正误勾"
python3 scripts/progress.py note 1-2 --text "只扒完前四小节；整项尚未结束"
python3 scripts/progress.py week-note 1 --text "实际产出 / 下一步 / 卡点"
python3 scripts/progress.py checkin --on 2026-09-06 --minutes 25 --note "实际完成最低剂量"
python3 scripts/progress.py uncheckin --on 2026-09-06 --reason "更正日期"
python3 scripts/progress.py reschedule 1-3 --date 2026-09-13 --reason "经本人确认顺延"
python3 scripts/progress.py mode --start 2026-10-05 --end 2026-10-10 --kind night
python3 scripts/progress.py clear-mode --start 2026-10-05 --end 2026-10-10

# 旧备份只并入状态，不改排期；默认只增加完成记录，不用旧备份取消较新的完成项
python3 scripts/progress.py import-plan --file /path/to/plan.backup.json
python3 scripts/progress.py fault list --query "真空"
python3 scripts/progress.py fault add --file /path/to/record.local.json
python3 scripts/progress.py fault update FM-0001 --file /path/to/patch.local.json
python3 scripts/progress.py fault import --file /path/to/faults.backup.json
python3 scripts/progress.py fault export-sanitized --output data/share-draft.local.json --reviewed

python3 scripts/sync-plan.py         # 只生成视图，不改 JSON
python3 scripts/sync-plan.py --check # 检查是否漂移，不写文件
```

歌曲发布项及 `song1 / song2 / song3` 交付勾选需 `--evidence` 提供真实发布链接；完整验收仍由 agent 按作品文件与本人确认核对。
`fault add` 输入对象可只给 `symptom`，其余字段按已知内容补，不能用模板虚构经历。输入临时文件须用 `.local.json`，写入后删掉不需要的临时副本。

#### HTML 为什么能直接看，但不能偷偷改硬盘

- 每个 HTML 内嵌的是**上次同步的文件快照**，无需网络、无需浏览器缓存就可阅读。在文件查看器中也能看。
- 浏览器安全限制不允许网页悄悄修改任意磁盘文件。需要手动编辑时，Chrome / Edge 可点击“连接项目 JSON”授权；连接后只写入所选文件。
- 网页写 JSON 后，其他静态视图由 agent 再同步；普通用户沿用对话流程即可避免这一步。
- 不支持文件接口的浏览器可“临时编辑”，缓存仅为草稿；或导出 JSON 交 agent 合并。页面会明确提示**没有写回项目**，绝不伪装成成功。
- 浏览器旧缓存只在主动“恢复旧草稿”后打开；不会自动盖掉 agent 已记录的状态。导入旧备份也先开成草稿，不直接覆盖正本。

#### 保密与“本地”的边界

`*.local.*` 与 `.backups/` 被 Git 忽略；公开故障 HTML 始终只是空白工具壳。Markdown / CSV 原始导出同样含敏感内容，只留本地。
脱敏采用字段白名单：删除型号 / 编号 / 报警 / 条件 / 路径，也不输出内部 ID、精确时间戳、配置、历史和未知字段；正文替换敏感词，日期只到月。
**脱敏结果仍是候选稿，不是公开许可。** 自由文本、组合信息和企业政策都须人工复核；`--reviewed` 只是确认理解这一限制。

**当前项目目录与用户电脑不是自动双向同步的。** Arena 工作区中的文件能在此项目继续使用，但不会悄悄写进 Windows 硬盘。
换 agent / 换机器要带上最新 JSON；公开 Git 默认不携带私有故障，须通过企业允许的私有方式迁移。
Git 忽略不是加密，也不隔离云平台。禁止出厂的日志不能交给未经授权的云端 agent，只能在获准的本机环境处理。

| 7 | **现场搭工作流** | W12 要做封面了才开始搭，超时 | W12 之前固定一个模板 |
